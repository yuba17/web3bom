# Run Benchmark Agent

Execute a benchmark execution plan generated by `run_benchmark.py --mode agent`.

## Input

The user provides a path to `execution_plan.json` as argument:
```
/run-benchmark-agent benchmarks/yieldoor/bench_session/execution_plan.json
```

## Execution Protocol

### 1. Load Plan

Read the `execution_plan.json` file provided as argument. Parse it as JSON.

Check for `checkpoint.json` in the same directory:
- If exists: load `completed_steps` set, announce resume, skip completed steps
- If not: fresh run

### 2. Resolve Execution Order

Group steps into sequential batches:
- Steps whose `depends_on` are all satisfied can run in the current batch
- Steps with the same `parallel_group` launch as multiple Agent tools in ONE message
- `depends_on: ["parallel_group:X"]` means wait for ALL steps in group X

### 3. Execute Each Batch

For each batch of runnable steps:

**Agent steps** (`type: "agent"`):
- Launch using the Agent tool with `prompt` from the step
- Set `mode: "bypassPermissions"` for autonomous execution
- If step has `parallel_group`, launch ALL steps in the group as concurrent Agent tool calls in a SINGLE message
- Respect `timeout` — if an agent hasn't responded, note it as failed
- If `prompt` is `"__DYNAMIC__"`, the preceding `generate` step should have provided the real prompt

**Bash steps** (`type: "bash"`):
- Execute using the Bash tool with `command` from the step
- Check exit code: 0 = success, non-zero = failure

**Gate steps** (`type: "gate"`):
- Execute using the Bash tool with `command` from the step
- If exit code != 0: **HALT execution**. Report which gate failed and why.

**Generate steps** (`type: "generate"`):
- Execute using the Bash tool with `command` from the step
- Parse stdout as JSON array of new step objects
- Insert these steps into the in-memory execution queue AFTER the current step (do NOT modify the original plan JSON on disk)
- Steps with `prompt: "__DYNAMIC__"` that depend on this generate step get their prompt replaced with the prompt from the generated output

**Python steps** (`type: "python"`):
- Execute using the Bash tool with `command` from the step

### 4. Handle Failures

- If a step fails and has `retry > 0`: decrement retry, re-execute
- If a step fails with no retries left: mark as failed, continue to next step (unless it's a gate)
- Gate failures: HALT. Report the failure and stop.

### 5. Write Checkpoints

After each batch completes, write `checkpoint.json` in the same directory as the plan:
```json
{
  "plan_file": "<path to execution_plan.json>",
  "completed_steps": ["step_id_1", "step_id_2"],
  "failed_steps": {"step_id": {"error": "reason", "retries_left": 0}},
  "current_batch": 5,
  "last_updated": "2026-04-05T12:30:00Z"
}
```

Use Bash tool to write: `python3 -c "import json; ..."`

### 6. Progress Reporting

After each batch:
- Print: `[Batch N/M] Completed: step_id_1, step_id_2 (Xm Ys elapsed)`
- If any steps failed: `[WARNING] Failed: step_id (reason)`
- Every 5 batches: print overall progress summary

### 7. Final Summary

After all steps complete:
- Print total elapsed time
- Print steps: completed / failed / skipped
- If ground-truth scoring was included, print the scoring output
- Print path to `findings_all.json`

## Resume Protocol

If `checkpoint.json` exists when skill starts:
1. Read completed_steps set
2. Skip ALL steps whose ID is in completed_steps
3. Re-resolve execution order with remaining steps
4. Announce: "Resuming from checkpoint — {N} completed, {M} remaining"
5. Continue normal execution

## Important Notes

- NEVER modify the original `execution_plan.json` — it's an audit trail.
- Write all step outputs to `bench_session/step_outputs/{step_id}.json`
- If a generate step fails, all steps depending on its output are automatically skipped.
