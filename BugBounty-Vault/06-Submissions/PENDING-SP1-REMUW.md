# PENDING — SP1 Missing REMUW instruction type in DivRem AIR constraints

## Status: VERIFIED, ready to write report and submit tomorrow

## Bug Location
- **File**: `crates/core/machine/src/alu/divrem/mod.rs`
- **Lines**: 1194-1209 (v6.0.0 tag)
- **Commit**: v6.0.0 (production release specified by bounty)

## The Bug
`calculated_instr_type` computes instruction type as weighted sum of 7 opcode flags, but REMUW is MISSING:

```rust
// Line 1194-1200: defines 7 instruction types (DIVU, REMU, DIV, REM, DIVW, REMW, DIVUW)
// MISSING: let remuw_instr_type = Opcode::REMUW.instruction_type().0 as u32;

// Lines 1202-1209: sum has 7 terms
let calculated_instr_type = local.is_divu * divu_instr_type
    + local.is_remu * remu_instr_type
    + local.is_div * div_instr_type
    + local.is_rem * rem_instr_type
    + local.is_divw * divw_instr_type
    + local.is_remw * remw_instr_type
    + local.is_divuw * divuw_instr_type;
    // MISSING: + local.is_remuw * remuw_instr_type
```

Compare with `base_opcode` calculation (lines 1170-1192) which CORRECTLY includes all 8 opcodes including REMUW.

## Evidence
- `base_opcode` has 8 terms (line 1185-1192): ✅ includes `is_remuw * remuw_base_expr`
- `calculated_instr_type` has 7 terms (line 1202-1209): ❌ MISSING `is_remuw * remuw_instr_type`
- When `is_remuw = 1`, `calculated_instr_type = 0` (invalid)
- The program table lookup with `instr_type = 0` will fail → proof generation fails

## Impact
- **Completeness bug**: Any Rust program using unsigned 32-bit remainder (`u32 % u32` which compiles to REMUW instruction) CANNOT be proved
- **Severity per bounty matrix**: Completeness + High Impact + High Likelihood = Medium ($1K-$5K)
- REMUW is a standard RISC-V RV64M instruction, commonly generated by Rust compiler
